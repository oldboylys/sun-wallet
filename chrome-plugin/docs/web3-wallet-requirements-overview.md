# Web3 Wallet 功能需求总览（V1）

## 1. 目标与范围

本需求文档用于定义 `SUN Wallet` 浏览器扩展的核心能力，作为后续 PRD、研发排期、测试验收的统一输入。

- **产品形态**：Chrome 扩展钱包（Popup 应用）
- **网络范围**：EVM 系（优先 ETH Mainnet / Sepolia）
- **当前阶段**：MVP（基础钱包流程 + 首页骨架 + 发送/接收骨架）
- **非目标（V1 不做）**：跨链桥、复杂 DeFi 聚合交易、硬件钱包深度集成

## 2. 用户与场景

- **新手用户**：首次创建钱包、备份助记词、基础收发币
- **迁移用户**：通过助记词或私钥导入已有钱包
- **高频用户**：快速查看资产、复制地址、收款二维码、发起转账

## 3. 核心功能模块

### 3.1 账户与安全

- 解锁（密码输入，已实现：首次设密 + 本地哈希校验解锁）
- 忘记密码说明与重置流程
- 钱包创建（助记词展示 + 记忆校验）
- 钱包导入（助记词 / 私钥）
- 本地数据存储（后续需加密）

### 3.2 资产与首页

- 账户切换入口
- 总资产估值展示
- 币种列表（余额、法币价值、涨跌）
- 快捷操作区（发送 / 接收 / 兑换 / 历史）
- 底部导航（首页 / 市场 / DApp / 我的）

### 3.3 交易流程

- 发送页（收款地址、金额输入）
- 收款页（地址 + 二维码）
- 交易确认页（预留：gas、nonce、总费用）
- 交易结果页（预留：成功 / 失败）

### 3.4 系统能力（基础设施）

- 状态管理：`zustand`
- 表单校验：`zod` + `react-hook-form`
- 链交互：`viem`（RPC client）
- 持久化：`chrome.storage.local` 封装
- 二维码：`qrcode`

## 4. 关键业务规则

- 助记词与私钥仅在本地处理，不上传服务端
- 任何风险操作（重置钱包）需二次确认与风险提示
- 未完成前置条件（如备份确认）不得进入下一步
- UI 统一遵循 `UI_STYLE_GUIDE.md`（组件化 + design token）

## 5. MVP 验收边界（建议）

- 必须完成：登录、忘记密码说明、首页、发送、接收（含二维码）
- 可占位：交易确认、交易历史、DApp 浏览、市场页
- 不可占位：关键输入交互、按钮状态（disabled/hover）、错误提示

## 6. 风险与依赖

- **风险**：私钥明文存储、RPC 不稳定、地址输入错误导致资产损失
- **依赖**：稳定 RPC、后续密码学加密方案、交易签名流程设计
- **合规提示**：发布前需补齐免责声明与风险告知文案

## 7. 版本路线（建议）

- **V1（当前）**：核心流程骨架可用
- **V1.1**：发送确认 + 广播交易 + 交易结果页
- **V1.2**：多账户管理、网络切换、地址簿
- **V2**：代币发现、DApp 连接授权、签名弹窗、Swap 深化
